# 中文说明告警与冒烟报告修复方案

版本：v3，2026-10-30，已实施并完成本轮自检。用户提供库存 350 项的当前截图并明确要求“开始实施”。执行两项程序修复；资料维护按同一批准 ECC 来源的当前状态处理：原定 18 项，加上实施前新增变化的 strategic-compact、tinystruct-patterns、typescript-patterns，共 21 项，均逐项审读后才采纳。范围调整用于完成当前 350 项资料修复，不涉及其他来源、技能安装或基线重置；v2 保存在本次本机证据目录。后续以本文件的版本及实际证据作为实施和验证依据，测试索引只引用本文件。实际结果见 [修复记录](../docs/note-freshness-repair-2026-10-30.md)。

## 目标与依据

解决已复现的两个程序问题，并安排来源变化后的资料复核：

- BUG-NOTES-UI-001：多个待复核项生成重复、无技能定位入口的全局告警。
- BUG-SMOKE-REPORT-001：真实检查失败后，旧的通过报告继续留在固定报告路径。
- 资料维护：原定确认 16 条说明并补齐两项；按当前 350 项来源再审读两条发生变化的说明，并补齐 typescript-patterns，共复核 18 条现有说明、补齐 3 条新增说明。

故障证据见本机 [排查记录](../.local/diagnostics/note-stale-2026-10-30/diagnosis.md)、[实时库存与摘要](../.local/diagnostics/note-stale-2026-10-30/live-inventory.json)、[界面复现](../.local/diagnostics/note-stale-2026-10-30/ui-observation.json)、[失败报告复现](../.local/diagnostics/note-stale-2026-10-30/smoke-failure.json)。现有规则见 [阅读器契约](../docs/contract.md)，测试索引见 [TESTS.md](../TESTS.md)。

排查快照为 349 项来源、347 条笔记，其中 331 verified、16 stale、2 missing；这是证据快照，不是未来测试的固定库存要求。16 条旧摘要均匹配 10 月 29 日源文件指纹，当前来源确实变化，版本号仍为 2.2.3。完整文件摘要判定有效；尚未证明这 16 条中文说明均需改写。

## Council 取舍与建议

| 取舍 | 推荐 | 依据与代价 |
|---|---|---|
| 程序修复与内容复核顺序 | 先修程序反馈，再完成资料维护 | 先保证告警可读、报告可信；程序阶段完成时，真实 stale/missing 仍可存在。 |
| 告警范围 | 全库统计，明确标注范围；默认折叠受影响项 | 筛选不隐藏其他技能的真实状态，也不再展开重复文案占据列表；条目链接负责定位。 |
| 报告含义 | 最近一次获准启动的运行；保留运行身份 | 沿用单个 smoke.json 入口；不增加历史报告管理功能。并发运行快速拒绝，不能覆盖活动运行。 |
| 旧正文不完整 | 有匹配旧全文时审读差异；没有时重新审读当前全文和现有中文 | 不把缺失旧全文变成无限等待，也不宣称重建了未取得的历史差异。 |

Architect、Skeptic、Pragmatist 均支持上述顺序与最小范围。Critic 要求明确中断、并发和源文再次变化时的证据边界。最强异议是“文件变化不能直接推出中文错误”；因此只对真正受影响的中文字段作修订。

## 第一阶段：两项程序修复

### A. 告警汇总与定位

1. 从现有 `/api/skills` 返回的 skills 状态生成来源级全库统计和受影响项列表，复用 id、callName、nameZh、status，不新增 API 字段或后端状态规则。
2. 对存在待复核或待整理项的来源显示一个默认收起的区域。例如：`ECC · 全库中文说明：16 项待复核，2 项待整理`。展开后分别列出两种状态，使用技能调用名／中文名及原生详情链接定位。
3. 在对应汇总已呈现时，不再逐条打印该来源重复的 NOTE_STALE 文案。其他诊断继续显示；没有对应技能的异常诊断不得被静默丢弃。
4. 原卡片和详情的状态提示继续显示。全库统计不随搜索、分类、标签或工作流阶段变化；打开问题项后返回列表，保留既有筛选。同页筛选变化保留已展开状态，不新增持久化偏好字段。
5. 全部说明已核对时不显示该问题区域。键盘可展开和打开链接；窄屏长调用名换行，默认状态不占据多屏高度。

预计修改 `web/app.mjs`、必要的 `web/style.css`，并把新浏览器场景接入既有 E2E 入口。无需为本问题修改 `src/server/app.mjs` 或诊断 schema。

### B. 冒烟报告表示本次运行

1. 沿用 `.local/acceptance/smoke.json`；保留现有成功报告字段，新增 runId、开始／结束时间、检查阶段和安全的失败原因。
2. 同一报告路径只允许一个运行。占用检查通过后，在读取配置、请求 API 和执行断言前，先完整发布本轮 `running` 报告；发布完成才开始本轮校验。并发调用明确失败退出，不覆盖活动报告。
3. 正常完成写 `passed` 并退出 0；配置、连接、解析、健康断言、详情读取等异常写 `failed` 并以非零码退出。库存、状态数、已检查正文数只记录本轮已观测事实，尚未取得的数据不得沿用上次值。
4. 每次用同目录临时文件写完整 JSON，再替换固定报告文件，避免留下半份报告。错误记录只含阶段、必要的技能 ID 和可理解原因，不写配置全文、凭据或宿主绝对路径。
5. 正常退出及可捕获异常释放运行占用。进程被硬终止时，不承诺完成终态写入；已发布的 `running` 只能视为未完成。遗留占用须先核实对应进程结束，再清理，不自动删除仍可能活动的占用。
6. 若报告目录本身无法写入，命令必须非零退出并明确说明本轮报告不可用；不能仅凭旧 JSON 判断本轮成功。运行身份用于区分本轮结果与历史产物。

预计修改 `scripts/smoke.mjs`，在 `tests/server/` 增加通过标准 Node 测试入口执行的 CLI 集成回归。使用临时目录和临时本地服务，不写真实验收目录。

零诊断、库存对应、每项 verified、摘要和完整正文校验均保持；不为当前来源异常放宽通过条件。

## 第二阶段：当前来源的逐项复核与新增说明

1. 开始时重新核对批准来源、安装 revision、活动笔记与当前状态，保存相关文件及 Git 暂存边界。最初 18 项与当前新增 3 项分别留证，处理集合固定为本次 350 项批准来源快照中的 21 个待处理 ID；不扩大到其他来源或未经审读的后续变化。
2. 逐项读取当前完整 SKILL.md，核对调用名、中文名、概括、场景、标签和分类。有已审旧全文时先验证旧摘要再看差异；无旧全文时按当前全文重新审读，并注明依据。
3. 现有中文仍准确的项保留文案；确受变化影响的项定向修订。每项保存旧／新摘要、来源 revision、判断和理由。只有审读完成的项才采纳当前 version/sourceHash。
4. 三项新增说明按现有笔记契约补齐真实调用名、中文用途、至少两个场景、分类、标签和当前摘要，不生成虚构用途或执行结果。
5. 写入前再次核对审读过的源文件摘要。来源再变化时，停止采纳该项的新摘要；保留旧证据，仅重查受影响项。批量写入前后验证其余 329 条记录内容不变，安装包仍只读。

数据修改限于 `data/learning-notes/ecc.json` 中上述 21 项，并保存本机逐项审读证据。此阶段不直接批量刷新摘要，也不预先认定全部变化项都需要改文案。

第一阶段运行 `npm test`、`npm run build`、`npm run check`、`npm run test:e2e`。测试通过后核对运行中的服务、全库状态汇总与最新 smoke 报告；实际部署／重启按确认范围执行。

两个完成结论分别记录：

- **程序修复完成**：重复匿名告警已替换为可定位汇总；失败运行不会继续冒充旧成功；新增回归和相关旧回归通过。真实资料 smoke 可以因尚未审读的说明继续失败，但本轮失败报告必须准确。
- **资料复核完成**：21 项逐项审读并采纳，真实来源未再漂移时 missing/stale 为零，完整资料 smoke 退出 0，详情正文逐项匹配。来源期间再变则保留实际失败，不宣称全部通过。

历史 `.local/source-baseline.json` 保留。`npm run baseline` 在相对历史基线仍有变化时继续非零，这是已知来源差异，不能通过覆盖基线消警；如需建立新批准基线，另行确认，不纳入本次两项程序修复。

## 实施边界与回退

保留既有技能搜索、来源／分类／标签／阶段筛选、详情、附件和新流程指南；不改技能安装、插件源码、网络策略、接口字段、哈希含义或无关恢复修改。本方案不包含自动提交、推送或发布网站。

实施前保存受影响文件、来源指纹和暂存差异。回退仅撤回本次获准差异；笔记如需回退则恢复对应记录，让当前来源与旧说明的差异重新如实提示，不将旧说明强制标记 verified。
