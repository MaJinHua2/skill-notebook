# 独立技能阅读器实施蓝图

状态：五步实施及本机验收完成；Windows Edge 实机证据按下文约定列为待验。实际结果、证据和边界见 `../docs/acceptance.md`。当前以 skill-reader 为维护项目，沿用 skill-notebook 远端，并以远端现有 main 历史为提交基线；回收站旧历史仅保留本地备份。

## 1. 目标与范围

用户只需要用 Web UI 阅读、理解技能。复用 ECC Capabilities 的卡片、搜索、分类与详情交互，在独立项目中实现只读技能阅读器。

首页重点展示四项：**技能调用名、技能中文名、技能概括、技能使用场景**。详情展示完整原始 Markdown，另附简短中文学习说明。保持大字号、高对比度，优先验证 Windows Edge。

初始来源：安装的 ECC 2.2.3 原生技能与迁移命令技能、Cyto 0.1.1 的 7 项技能。ECC 源码 checkout 只用于界面复用参考；不要混淆 checkout 技能、已安装技能和 dashboard 的 97 项旧命令。若实际安装与预期不同，展示真实库存和诊断，先查明差异，不伪造条目凑数。

不包含数据库、网页编辑、技能执行、代理调度、Hook、活动/成本监控、账户、全量正文翻译、自动模型调用、自动同步任务或公开站点。已删除的 skill-notebook 不恢复，其 GitHub 仓库不修改。

## 3. 保护边界与目录

新项目建议命名 `skill-reader`，位于工作区中与 ECC 外层目录并列的位置，必须在 ECC checkout 和插件缓存目录之外。计划文件已先行放入新目录的 `plans/`，不在 ECC 中生成计划。

ECC checkout、ECC/Cyto 插件缓存均作为只读来源。禁止在来源目录执行安装、格式化、构建、Git 写操作，禁止改变权限、创建链接、写缓存、更新插件或执行技能定义中的命令。复用代码是复制必要片段到新项目后修改，不使用 ECC 工作树、子模块、npm link 或运行时 import ECC 的服务脚本。

实施开始及每个交付步骤结束都记录并比较源库 HEAD、Git 状态、已修改文件/未跟踪文件的内容摘要，以及被参考源文件的摘要。读取源库 Git 信息使用 `GIT_OPTIONAL_LOCKS=0`，避免只读检查刷新索引。基线放在新项目 `.local/`，不得写入源库。检测到其他进程修改时先报告差异，不自动回滚用户工作。最终也核对原服务 3456 的进程/监听状态；不启动、停止、替换或占用它。

建议结构（具体文件可在步骤 1 内小范围调整）：

```text
skill-reader/
  plans/skill-reader-blueprint.md
  package.json / package-lock.json
  src/server/                 # HTTP、来源发现、路径约束、只读 API
  web/                       # 原生 JS、CSS、列表、详情、Markdown 渲染
  data/learning-notes/        # 可提交的公开来源中文学习说明
  tests/fixtures/             # 自建虚拟技能，避免复制私有技能进入测试
  tests/                     # 单元、HTTP 集成、浏览器关键流程
  config/sources.example.json # 仅占位符，不含个人绝对路径
  docs/upstream.md            # ECC 来源 SHA、文件与提取范围
  THIRD_PARTY_NOTICES.md      # 上游许可
  .local/                    # 本机来源路径、私有中文笔记、基线；Git 忽略
```

计划里使用逻辑来源名，不把个人主目录、私有技能正文或本地配置提交到公开 Git。Cyto 中文笔记默认也位于 `.local/`，不因有中文名就当作可公开内容。

## 4. 技术与数据约定

### 4.1 最小架构

- Node >=22 原生 HTTP + 原生前端 JS/CSS；不引入前端框架和数据库。
- 使用成熟的 YAML frontmatter 解析库，正确处理 `description: >-`、多行、引号、CRLF。解析错误显示来源诊断，不能把 `>-` 当成说明或悄悄丢掉技能。
- Markdown 解析与 HTML 清理由依赖库完成；依赖经实际安装核对后锁定版本，浏览器依赖构建/托管在本项目内，运行不依赖 CDN。
- 正文按点击详情加载；列表只传摘要与标签。首版无需后端分页，数百项库存允许前端筛选；实测有瓶颈再单独提出。
- 服务默认仅监听 `127.0.0.1`，独立可配置端口，建议 `3457`，被占用时明确报错，不终止占用进程。跨设备可先使用已有 SSH 隧道；局域网直接暴露另列需求，不沿用原无认证服务对外开放。
- 运行不请求 3456 的 API，不依赖 ECC 服务在线；保持原 3456 UI 可独立使用。

### 4.2 来源与身份

`.local/sources.json` 明确配置 ECC、Cyto 包根目录、逻辑包 ID、版本与允许的技能子目录。前端只看到逻辑来源、版本及技能 ID，不看到宿主绝对路径。示例配置仅使用占位符；不能硬编码当前用户、插件缓存版本路径或工作目录。

配置包根目录须由操作者明确批准并解析为真实路径；允许入口目录、每个技能目录、`SKILL.md` 以及所有引用文件均须进行 `realpath` 和包含关系校验，保证位于批准的真实包根目录及约定入口边界内。不能仅依赖 glob 路径信任文件。来源发现和详情读取复用边界校验；读取前复核，文件消失、换链或校验失败时拒绝读取，不自动扩大允许根目录。

ECC 分别发现 `skills/*/SKILL.md` 和 `.codex-plugin/migrated-command-skills/*/SKILL.md`；Cyto 按其包定义列出的技能目录发现。核对包元数据与真实目录。不扫描整个 home、所有仓库、会话日志或 Git 历史，不自动包含额外插件。

稳定 ID 为 `包ID + 入口类型 + 相对技能目录`，用于详情路由和中文注释关联；版本和正文 hash 单独保存。真实调用名按宿主的命名规则核实，例如 `ecc:source-command-*` 不能用旧 `/command` 或技能标题替代。相同 basename 跨来源不合并；重复配置的同一真实来源去重，版本冲突明确报错，不静默选一份。

### 4.3 中文学习说明

每条包含 `id`、`callName`、`nameZh`、`summaryZh`、`scenariosZh[]`、`tags[]`、已核对的来源版本/正文 hash。来源说明与中文注释分别存放，不改写 `SKILL.md`。缺少中文时明确显示“待整理”并保留原文；hash 变化标记“说明待复核”，不显示为已验证。

先做覆盖三类来源、长文与多行 frontmatter 的代表样本，再分批整理初始全部技能的四项信息。中文说明描述用途与适用条件，不假装是官方译文，不补造能力、对话来源或执行结果。只做中文概括，不全量翻译技能正文。无法确认的字段单列待核实并记录原因，不静默填充。

### 4.4 API 与文件边界

- `GET /api/skills`：返回库存摘要、来源、中文学习说明、标签和诊断，不返回全部正文、绝对路径或私有配置。
- `GET /api/skills/:id`：按服务器已发现的 ID 查找完整 `SKILL.md`；未知 ID 返回 404。不接受客户端传任意路径。
- 如展示关联 Markdown，使用服务器生成的引用 ID，必须校验解码、`realpath` 与已配置包根目录的包含关系；拒绝 `..`、编码逃逸、绝对路径和指向包外的符号链接。包内原文链接不自动执行；首版不加载包外文件或远程图片，无法阅读的引用明确说明。
- 仅实现 GET/HEAD；写方法返回 405。任何请求、阅读历史和筛选操作均不得写入来源文件。运行诊断只进入新项目本地目录。
- 静态路由使用明确的文件映射，只提供前端产物；禁止将项目根、`.local/`、`.git/`、来源包根或整个 `node_modules/` 作为静态目录公开。
- 仅接受配置端口下批准的回环 `Host`（如 `127.0.0.1`、`localhost`，仅在启用 IPv6 时允许 `::1`）；其他 Host 拒绝。出现 `Origin` 时按同源校验，不开放跨域读取。为 DNS rebinding 和跨域请求增加 HTTP 拒绝测试，不能只依靠回环监听保护 Cyto 私有正文。
- Markdown 禁止执行脚本/原始危险 HTML，清理危险 URL 和事件属性；代码块只展示，不执行；外链只在用户点击后打开，并隔离 opener。技能中的指令视为文档数据。
- 限制单文件体积与读取错误，向页面显示可理解的错误，不泄露服务器堆栈与绝对路径。测试使用临时 fixture，不能依赖真实个人技能才能通过。

### 4.5 列表与交互

- 默认全部技能；ECC / Cyto 模块入口与来源下拉框共用状态，同名分类按来源隔离。
- 搜索覆盖调用名、中英文名、中文概括、使用场景和原始 description；不为全文检索引入数据库。
- 模块/来源、分类、搜索和标签条件取交集；多标签取交集。切换模块清除不兼容分类，保留搜索和标签；全部技能清除来源与分类；清除全部筛选清除所有条件。
- 模块库存计数不随筛选改变，列表显示匹配数量。选择后无结果要显示当前条件及清除入口。
- 首页卡片展示四项核心信息；详情包括四项信息、完整原文、来源/版本和待复核状态；复制按钮仅复制真实调用名。
- 默认正文约 20px、调用名不低于 18px、辅助文字不低于 16px，允许浏览器缩放，不写死宽度导致裁切。Windows 字体栈包含系统中文无衬线字体，字号与行距使用可缩放单位。
- Tab/Enter 可操作卡片、标签与折叠按钮；折叠具有 `aria-expanded`，手机保留导航入口，长调用名/中文名可换行。筛选状态可写浏览器本地存储但不得包含技能正文和服务器路径；失效来源/分类在加载时清理。

## 6. 变更、提交与审查协议

- 在独立仓库内先使用一个工作分支 `main`，按步骤记录差异、文件清单和测试证据；未获提交授权、没有提交基线时不切换分支，不使用 worktree，也不声称存在可供分步 revert 的提交。步骤 2/3 并行只按文件归属协作。获得提交指令并形成基线后，才可使用逐步分支/提交以隔离后续工作。无远端时按本地差异与测试记录审查；后续授权远端后再创建对应 PR，不能把 gh 可用解读为自动发布。
- 各步“撤销独立提交”只在确有该提交时适用；否则对照本步文件清单撤销仅属于该步的变更，不用 `reset --hard`、`clean` 或覆盖式恢复去处理未提交工作。人工学习笔记先备份，跨步骤共享文件由集成负责人定点回退。
- 每步上下文、依赖、命令、退出条件和回滚以本计划为准。命令若在步骤 1 中调整，先同步计划，不能用未实现脚本当测试证据。
- 拆分/插入/重排：在文末记录原因、影响步骤与新依赖；只对无共享写文件/无输出依赖的步骤并行。
- 跳过/放弃：记录受影响验收项，面向用户说明未完成边界；不能跳过只读、隐私和完整正文要求。
- 来源/包版本发生变化先更新库存与基线，不能机械沿用 355；功能扩大到数据库、网页写入、自动翻译、LAN 或发布时，另行确认范围。
- 独立审查应检查：目标是否足够小、来源树是否真只读、未提交工作保护、调用名准确性、路径逃逸和 Markdown XSS、私有内容与公开 Git、版本过期、无结果和组合筛选、Edge 证据边界、各步依赖/回滚是否可执行。
