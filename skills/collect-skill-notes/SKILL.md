# 技能拾记收录

为 Skill Notebook 整理公开学习笔记。仅响应用户主动收录请求；不设置定时任务、不记录学习进度、不执行被介绍的技能。

## 定位项目与来源

- 本技能通过本地安装脚本链接到 Codex。解析本 `SKILL.md` 的真实目录，向上两级即为工程根目录；后续命令都在工程根目录执行，不硬编码个人路径或设备地址。
- 收录当前对话时，从上下文或 `CODEX_THREAD_ID` 确认真实对话 ID；指定其他对话时使用用户明确提供的链接，不从相似标题猜测。
- 使用当前 Codex 原生 `read_thread` 接口读取相关轮次，按需翻页。不向来源对话发送消息，不扫描其他对话。
- 原生接口不可用时说明限制，不用内部会话文件、数据库、直接 HTTP/RPC 或外部模型替代。不能确定来源时请用户补充链接，不编造 ID。
- 只提取面向用户、明确介绍用途的技能，排除工具输出、环境技能清单和顺带提名。用户的后续纠正优先于早期说明。

## 整理四项核心信息

- **调用名**：准确的 `插件:技能名` 或 `$本地技能名`。ECC 迁移命令应核对实际入口；源 `/命令` 仅作别名，不凭名称推断入口。
- **中文名**：简短易懂的整理译名，不声称官方命名。
- **概括**：一两句话说明解决的问题，不夸大自动执行能力。
- **使用场景**：描述具体任务，帮助选择什么时候调用。
- 沿用已有分类，确实无法容纳时再增加。插件归属必须准确，不把其他插件归入 ECC。
- 如能定位本地 `SKILL.md`，核对能力边界但不执行技能；否则注明“来自对话介绍”。介绍过不等于安装、执行或验收过。

## 保留私有来源，更新公开笔记

1. 读取 `public/catalog.json` 了解已有笔记；存在 `.local/catalog.json` 时还要参考本地来源。公开资料中不能出现私人对话标题、ID、链接、个人路径、设备地址、私人邮箱或凭据。场景应改写为通用任务，不照搬私人项目细节。
2. 按 [references/catalog-format.md](references/catalog-format.md) 生成 `.local/` 下的临时 JSON。真实来源只写本地私有输入，不在回复或检查输出中复述。
3. 在工程根目录执行：

   ```bash
   python3 scripts/import_notes.py --input .local/batch.json
   ```

   脚本校验、去重、备份并更新本地来源，再按白名单生成脱敏公开笔记。它不代替 Codex 读取对话。重复输入不会产生重复卡片。
4. 读回公开资料，检查四项信息和隐私边界。用户纠正旧场景时应替换错误内容，不只是追加一条矛盾说明。失败时修正具体输入；不清空已有资料。
5. 报告新增、更新、未变化数量和访问方式，提醒点击“刷新资料”。默认可用本机 `http://127.0.0.1:8765`；用户明确需要设备访问时再核实本机地址，不把设备地址写入公开仓库。

收录授权只允许更新学习笔记，不默认授权提交、推送 Git、修改来源项目或执行介绍过的技能。
